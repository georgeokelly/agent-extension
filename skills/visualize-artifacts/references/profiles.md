# Visual Artifact Profiles

Use these profiles to choose source artifacts, delivery artifacts, and owners.
They are artifact-packaging profiles, not chart-selection or image-generation
instructions.

## Profile Table

| Profile | Use When | Owner | Source Artifact | Delivery Artifact | Hard Boundary |
| --- | --- | --- | --- | --- | --- |
| `technical-diagram` | Workflow, architecture, data path, pipeline, sequence, lifecycle, or system structure needs precise labels and edges. | `drawio` when native editable mxGraph is required; otherwise deterministic Mermaid/SVG/HTML/Slides. | `.drawio`, `.mmd`, `.svg`, `.html`, or slide source. | SVG, PNG, PDF, HTML, or deck export. | Do not use AI raster as the sole source for exact diagrams. |
| `data-chart` | The visual is derived from a dataset, table, metric series, or statistical question. | `visualize-data`. | Dataset plus chart source generated by `visualize-data`. | PNG, SVG, PDF, or HTML chart export. | Do not pick chart types, load data, inspect distributions, or write plotting code here. |
| `benchmark-chart` | Performance numbers, model comparisons, latency/throughput, ablations, or report-ready benchmark graphics. | `visualize-data` for chart generation. | Benchmark data plus chart source. | Prefer SVG when trusted and sanitized; use 2x PNG when fixed layout is safer. | Do not infer metrics or choose visualization from raw data here. |
| `hybrid-diagram` | AI-generated background or mood layer plus exact deterministic labels, nodes, arrows, or UI overlay. | `imagegen` owns raster layer; deterministic renderer or `drawio` owns exact overlay. | Raster background plus overlay source. | Flattened PNG/WebP plus editable overlay/source files. | Do not merge the only source into one approximate raster. |
| `ai-background` | Decorative or conceptual raster background, product mood, stylized system atmosphere, scene, texture, or cover image. | `imagegen`. | Generated raster source. | PNG or WebP depending on delivery need. | Do not ask AI raster to carry exact labels, arrows, or data. |
| `large-raster` | Screenshots, heatmaps, photos, large bitmap exports, or inspection-heavy raster content. | Source-specific owner; `imagegen` only if AI-created. | Original screenshot/plot/photo or generated raster. | WebP for size, PNG for lossless inspection. | Do not discard a reproducible source when future edits are likely. |

| `logo-icon` | Brand/icon discussion, early raster concept, or delivery packaging for icon assets. | Native vector/code tools for existing SVG/vector systems; `imagegen` only for explicit raster concept images. | SVG/vector/source code for production icons; raster only for concept art. | SVG for production vector; PNG/WebP previews as needed. | Do not regenerate or match an existing logo/icon system as AI raster by default. |

## Source-Of-Truth Rules

- If exact text, arrows, data values, or layout must be maintained, the source
  must be deterministic and editable.
- If future edits are likely, keep source and delivery files together or report
  both paths.
- If the source is generated by another skill, do not duplicate that skill's
  internal workflow. Ask for or route to its output.
- If the user's request is only "make this deliverable WebP/PNG/SVG/PDF",
  treat it as a format/package decision and preserve the existing source.

## `data-chart` / `benchmark-chart` Scope Limits

`data-chart` and `benchmark-chart` exist so this skill can specify artifact
policy for chart outputs. They must not include:

- chart type recommendation
- EDA
- dataset loading or cleaning
- plotting code
- benchmark interpretation
- copies of `visualize-data` chart-selection tables

Route those tasks to `visualize-data`, then apply format/source packaging policy
to the produced chart artifacts.
